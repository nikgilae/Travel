# Экран маршрута (Дни / Карта / Бюджет)

> **Роут:** `/trip/:id/plan`
> **Модуль:** Поездки, POI
> **Файл:** `frontend/src/pages/TripPlanScreen.jsx` (+ `.css`) — крупнейший файл фронтенда (~1810 строк)

## Обзор
Центральный экран приложения — детальный просмотр и донастройка сгенерированного ИИ маршрута поездки. Три вкладки: список точек по дням, карта, разбивка бюджета.

## Layout
- **Хедер:** кнопка «назад» (→ Дашборд), заголовок «ВАШ·МАРШРУТ», кнопка «поделиться» (копирует URL в буфер), название города + количество дней, крупный заголовок «{ГОРОД}, {РИТМ}», кнопка инфо (открывает `SummarySheet` — нижний шит с `ai_summary` и `total_budget_estimate`)
- **Табы:** ДНИ / КАРТА / БЮДЖЕТ

## Загрузка данных
- **API:** `GET /trips/{tripId}` (Bearer) → объект поездки со всеми POI (`pois[]`), включая для каждой точки: вложенный объект `poi` (id, name, description, is_indoor, lat, lon, google_place_id), `day_number`, `sequence_order`, `poi_status`, `planned_start_time`, `start_time`/`end_time`, `activity_level`, `ai_tip`, `budget_estimate`

## Вкладка «ДНИ»

### Регионы
- Горизонтальный селектор дней (день недели, число, индикатор «сегодня»)
- Карточка «Ритм · День N» с кастомным SVG-графиком ритма (сплайн Катмулла — Рома по времени начала и уровню активности точек; если данных <2, рисуется декоративная заглушка)
- Таймлайн точек, две зоны:
  - **Основные POI** (сплошная лаймовая линия): время, название, бейдж бюджета, AI-совет или описание, действия «ЗАМЕНИТЬ» / «ДЕТАЛИ» / удалить
  - **Запасные POI** (пунктир, приглушённые; скрываются после финализации дня): кнопка «+ ДОБАВИТЬ»

### Взаимодействия

#### Финализация дня
- **Триггер:** «ФИНАЛИЗИРОВАТЬ ПЛАН ДНЯ»
- **API:** `POST /trips/{tripId}/days/{day}/finalize/auto-main` (Bearer)
- **Поведение:** локально сохраняется снэпшот текущих POI (для отмены), ответ сервера заменяет состояние `trip`, день помечается финализированным в клиентском `Set` (`finalizedDays`)
- **Важно:** `finalizedDays` — **чисто клиентское состояние, не персистится**; при перезагрузке страницы статус «финализирован» сбрасывается (хотя сами данные точек на бэкенде остаются финализированными — `is_selected=True`, порядок задан)

#### Отмена финализации («Вернуть к редактированию»)
- Модалка подтверждения → восстанавливает локальный снэпшот из памяти
- **Нет вызова бэкенда** — после перезагрузки страницы (когда снэпшот в памяти утерян) отменить финализацию таким образом уже нельзя

#### Замена точки
- **Триггер:** «ЗАМЕНИТЬ» → инлайн-пикер альтернативных точек
- **API:** `POST /trips/{tripId}/pois/swap` `{promote_poi_id, demote_poi_id}` → заменяет `trip` ответом сервера, toast «МЕСТО ЗАМЕНЕНО ✓» / «МЕСТО ДОБАВЛЕНО ✓»

#### Удаление точки
- **Триггер:** иконка корзины → модалка подтверждения
- **API:** `DELETE /trips/{tripId}/pois/{poiId}`
- **Поведение:** оптимистичное удаление из локального `trip.pois`

#### Детали места (`PlaceDetailsModal`, нижний шит)
- Если у точки нет `google_place_id`: `GET /places/find?input="{name} {city}"` → получить `place_id`
- `GET /places/details?place_id=...` → рейтинг, адрес, часы работы, редакционное описание
- `GET /places/photo?photo_reference=...&maxwidth=400` (Bearer) → blob → object URL для картинки
- Ссылка «ОТКРЫТЬ В GOOGLE MAPS» — внешний переход

## Вкладка «КАРТА»
- Компонент `TripMap` (Google Maps JS API через `@react-google-maps/api`, ключ `VITE_GOOGLE_MAPS_API_KEY`)
- Селектор дня (чипсы)
- Геокодирование точек без координат — на клиенте через Google Geocoder, кэшируется в состоянии
- Основные точки — пронумерованные лаймовые маркеры; запасные — буквенные серые (скрыты, если день финализирован)
- Полилиния между основными точками рисуется **только после финализации дня**
- Геопозиция пользователя — синяя точка (`navigator.geolocation`)
- Нижняя горизонтальная лента карточек точек, синхронизированная с картой (пан/зум/выбор маркера)
- Клик по маркеру/карточке → Google InfoWindow (время, тег «в помещении/на улице», «Как добраться →» — открывает нативные маршруты Google Maps)

## Вкладка «БЮДЖЕТ» (`BudgetTab`)
- **Полностью клиентское вычисление**, без дополнительных API-вызовов
- Парсит свободнотекстовые строки `budget_estimate` регулярными выражениями, поддерживает 13 валютных обозначений (`₽ ¥ € $ £ ₺ ฿ ₹ ₸ zł ₩ AED` и др.), учитывает формулировки «на человека» (умножение на `group_size`), усредняет диапазоны
- Агрегирует суммы по всем «основным» точкам — по дням и по поездке целиком
- Раскрывающаяся детализация по дням
- Явная пометка: проживание и транспорт **не включены** в расчёт и должны бюджетироваться отдельно

## API-зависимости (сводно)

| API | Метод | Путь | Вкладка/действие |
|---|---|---|---|
| Детали поездки | GET | `/trips/{id}` | Загрузка страницы |
| Финализация дня (авто) | POST | `/trips/{id}/days/{day}/finalize/auto-main` | Кнопка «Финализировать» |
| Замена точки | POST | `/trips/{id}/pois/swap` | «ЗАМЕНИТЬ» |
| Удаление точки | DELETE | `/trips/{id}/pois/{poiId}` | Иконка корзины |
| Поиск place_id | GET | `/places/find` | Открытие «ДЕТАЛИ» (если нет `google_place_id`) |
| Детали места | GET | `/places/details` | «ДЕТАЛИ» |
| Фото места | GET | `/places/photo` | «ДЕТАЛИ» |

## Связи со страницами
- **Откуда:** Дашборд, Шаг 6 онбординга (после генерации), «Рядом»/Чат поездки (через таб-бар)
- **Куда:** `/dashboard/routes` (назад), `/trip/{id}/chat`, `/trip/{id}/nearby` (таб-бар)

## Бизнес-правила / замечания
- Двойная загрузка Google Maps JS SDK: один раз глобально в `index.html`, второй раз через `useJsApiLoader` в `TripMap.jsx` — потенциальный конфликт/избыточность.
- Статус финализации дня рассинхронизирован между клиентом (`finalizedDays` Set в памяти) и сервером (реальное состояние `is_selected`/`sequence_order` в БД) — после перезагрузки страницы UI определяет «финализирован ли день» заново по наличию `sequence_order`/`is_selected` у точек, а не по client-side Set, поэтому визуально показывает корректное состояние, но кнопка «Вернуть к редактированию» становится недоступной для отмены (снэпшот утерян).
