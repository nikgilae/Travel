# Онбординг — Шаг 6: «Зачем ты едешь в {город}?» (финальный, создание маршрута)

> **Роут:** `/onboarding` (шаг 6 из 6)
> **Модуль:** Онбординг
> **Файл:** `frontend/src/pages/OnboardingFinalQuestion.jsx` (+ `.css`)

## Обзор
Последний шаг онбординга: сбор свободного текстового пожелания и запуск создания поездки + AI-генерации маршрута. Единственный шаг, который реально вызывает backend для создания сущностей.

## Layout
Заголовок с подстановкой города («Зачем ты едешь в {city}?») → textarea для пожеланий → кнопка «Создать маршрут» → полноэкранный спиннер на время создания/генерации.

## Поля

| Поле | Тип | Обязательное | Примечание |
|---|---|---|---|
| Пожелания (`notes`) | Textarea | Нет | Передаётся как есть в поле `notes` при генерации |

## Взаимодействия

### Отправка («Создать маршрут»)
- **Триггер:** нажатие «Создать маршрут»
- **Последовательность:**
  1. `update({notes})` — сохранить в контекст
  2. `POST /trips` `{country_id, city_id, purpose:'leisure', budget, group_size, other_information:['balanced'], start_date, end_date}` (Bearer)
  3. Сохраняет `current_trip_id`, `trip_display_data`, обновляет карту `trip_meta` в `localStorage` (для последующего отображения города без повторных запросов)
  4. `POST /trips/{id}/generate` `{interests, notes}` — запускает AI-генерацию
  5. При успехе → `navigate('/trip/{id}/plan', {state:{city, groupType, rhythm}})`
- **Во время ожидания:** полноэкранный спиннер «Складываю маршрут…»
- **Ошибка:** отображается инлайн, состояние загрузки сбрасывается — пользователь может повторить попытку

## API-зависимости

| API | Метод | Путь | Триггер |
|---|---|---|---|
| Создать поездку | POST | `/trips` | Нажатие «Создать маршрут» |
| Сгенерировать маршрут | POST | `/trips/{id}/generate` | Сразу после успешного создания поездки |

## Связи со страницами
- **Откуда:** Шаг 5
- **Куда:** `/trip/{id}/plan` (после успеха)

## Бизнес-правила / замечания
- `purpose` на этом шаге **всегда хардкодится как `'leisure'`** — отдельного UI-шага выбора цели поездки (отдых/работа/учёба/другое) не существует, несмотря на то что backend это поддерживает.
- `other_information` всегда отправляется как `['balanced']` — жёстко закодированное значение, не связанное с реальным выбором пользователя (ритм поездки нигде явно не выбирается — см. общее замечание в README про `OnboardingStep3`).
- Если на Шаге 3 даты были пропущены, шаг 4 генерации (`POST /trips/{id}/generate`) завершится ошибкой 500 (см. страницу Шага 3) — пользователь увидит generic-сообщение об ошибке.
- Создание поездки и генерация маршрута — два последовательных сетевых вызова; если второй (генерация) упадёт, поездка **уже создана** в БД (первый вызов прошёл успешно) — пользователь окажется с пустой поездкой без сгенерированных точек, которую при повторной попытке форма не переиспользует (создаст новую).
