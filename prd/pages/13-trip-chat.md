# Чат по поездке

> **Роут:** `/trip/:id/chat`
> **Модуль:** AI-чат
> **Файл:** `frontend/src/pages/TripChatPage.jsx` → обёртка над `ChatScreen.jsx` (`mode="trip"`, светлая тема)

## Обзор
Стейтфул AI-ассистент с полным контекстом конкретной поездки, способный не только отвечать на вопросы, но и **напрямую менять маршрут** (финализировать день, менять бюджет/цель, убирать точки) через function calling — все изменения выполняются теми же сервис-методами, что и explicit-действия в UI.

## Layout
Идентичен общему чату (лента + чипсы + поле ввода), но с индикатором статуса соединения (ОНЛАЙН / обратный отсчёт переподключения / ОФЛАЙН).

## Взаимодействия

### Подключение
- **Протокол:** WebSocket, `${WS_BASE}/trips/{tripId}/chat?token={access_token}` (`WS_BASE` = `API_BASE` с заменой `http→ws`)
- При успешном подключении бэкенд присылает канонное приветствие: «Привет! Я ваш тревел-консьерж…» — **пропускается**, если в модульном кэше `tripHistoryCache` для этого `tripId` уже есть сохранённая история сессии
- **Авто-переподключение:** до 5 попыток с 3-секундным обратным отсчётом в UI

### Отправка сообщения
- **Триггер:** ввод + отправка
- **Протокол:** сырой текст через `ws.send(msg)` (не JSON-конверт)
- **Тайм-аут:** если ответ не приходит за 30 секунд — индикатор «печатает» принудительно снимается, показывается системное сообщение об ошибке

### Предзаполнение из другой страницы
- Принимает `location.state.prefill` (приходит из «Рядом» при нажатии «В ЧАТ →» на карточке места) — подставляет в поле ввода готовый текст вида `Добавь "{название}" в мой маршрут`

### Чипсы-подсказки
- В обычном режиме: «Добавь ресторан на день 2», «Убери последнее место из дня 3», «Какая погода будет?»
- В режиме `live` (не достижим через текущий роутинг — см. ниже): другой набор подсказок

## Возможности агента (что он может сделать в диалоге)
| Что просит пользователь | Инструмент | Эффект |
|---|---|---|
| «Собери план», «сделай день N как ты предложил» | `tool_auto_finalize_day` | Финализирует день тем же алгоритмом ближайшего соседа, что и кнопка в UI |
| «Смени бюджет на люкс», «это деловая поездка» | `tool_update_trip_info` | Обновляет `budget`/`purpose` поездки |
| «Убери это место из дня» | `tool_remove_poi_from_day` | Мягко убирает точку (переводит в `additional`, снимает `is_selected`) — не удаляет физически |

Агент никогда не показывает пользователю сырые UUID точек — ссылается на них только по названию.

## API-зависимости

| API | Протокол | Путь | Примечания |
|---|---|---|---|
| Чат по поездке | WebSocket | `/trips/{trip_id}/chat?token=...` | Токен передаётся в query-параметре, а не в заголовке (ограничение протокола WS) |

## Связи со страницами
- **Откуда:** Экран маршрута / «Рядом» (с предзаполнением) — через таб-бар `TripLayout`
- **Куда:** таб-бар → `/trip/{id}/plan`, `/trip/{id}/nearby`

## Бизнес-правила / замечания
- История чата хранится **только в оперативной памяти вкладки** (`tripHistoryCache`, модульный кэш) — переживает переключение вкладок внутри SPA-сессии, но полностью теряется при перезагрузке страницы; backend пишет полный транскрипт в таблицу `messages`, но она не читается обратно приложением (известный технический долг).
- Флаг `live` (проверяется по вхождению `/live/` в путь) — **мёртвая ветка**: маршрута с сегментом `/live/` в приложении не существует, соответствующий набор чипсов-подсказок никогда не активируется в текущем роутинге.
- Ошибки внутри WS-сессии не проходят через обычный HTTP-обработчик исключений — они отдельно логируются и отправляются в Sentry/Telegram; клиент в этом случае получает нейтральное сообщение «Техническая ошибка сервера.».
