# Вход

> **Роут:** `/`
> **Модуль:** Аутентификация
> **Файл:** `frontend/src/pages/LoginPage.jsx` (+ `AuthPage.css`)

## Обзор
Стартовый экран приложения. Пользователь вводит email и пароль для входа; в зависимости от того, есть ли у него уже поездки, попадает либо в онбординг, либо сразу в дашборд.

## Layout
Единая центрированная форма: логотип/заголовок → поле email → поле пароль → кнопка отправки → блок ошибки (если есть) → ссылка на регистрацию.

## Поля

| Поле | Тип | Обязательное | Валидация | Примечание |
|---|---|---|---|---|
| Email | `input type=email` | Да | Браузерная HTML5-валидация email | |
| Пароль | `input type=password` | Да | Нет клиентской проверки сложности (в отличие от регистрации) | |

## Взаимодействия

### Отправка формы
- **Триггер:** нажатие «Войти» / submit формы
- **API:** `POST /auth/login` `{email, password}`
- **Успех:** сохраняет `access_token` и `user_email` в `localStorage`; если `is_first_login === true` → переход на `/onboarding`, иначе → `/dashboard/routes`
- **Ошибка:** текст ошибки (`err.message`, из поля `detail` ответа API) отображается в блоке `.auth-error` под формой. Backend отдаёт единый текст на неверные email/пароль, не раскрывая, что именно неверно

## API-зависимости

| API | Метод | Путь | Триггер | Примечания |
|---|---|---|---|---|
| Логин | POST | `/auth/login` | Submit формы | Без auth-заголовка |

## Связи со страницами
- **Откуда:** стартовая точка входа (`*` редиректит сюда же при отсутствии токена); также после логаута из Дашборда
- **Куда:** `/register` (ссылка), `/onboarding` или `/dashboard/routes` (после успешного входа)

## Бизнес-правила
- Нет проверки истечения токена при последующих визитах — если токен просрочен (>3 ч), пользователь останется «залогинен» на клиенте, но запросы к API начнут падать с 401 без автоматического редиректа на `/`.
