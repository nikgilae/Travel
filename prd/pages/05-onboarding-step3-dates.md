# Онбординг — Шаг 3: «Когда едем?»

> **Роут:** `/onboarding` (шаг 3 из 6)
> **Модуль:** Онбординг
> **Файл:** `frontend/src/pages/OnboardingDates.jsx` (+ `.css`)

> Примечание: несмотря на порядковый номер компонента в файловой системе, в реальном UI-флоу этот экран — шаг 3 (после «С кем вы»), реализован именно `OnboardingDates.jsx`, а не `OnboardingStep3.jsx` (тот не используется — см. [README](../README.md), раздел «Известные незавершённые участки»).

## Обзор
Выбор дат начала и окончания поездки через кастомный календарь.

## Layout
Заголовок «КОГДА ЕДЕМ?» → навигация по месяцам (рус. названия месяцев/дней) → сетка календаря с click-to-select диапазоном → индикатор количества дней → предупреждение при превышении лимита → кнопки «Продолжить» / «Пропустить».

## Поля

| Поле | Тип | Обязательное | Валидация |
|---|---|---|---|
| Дата начала | Клик по дню календаря | Нет (можно пропустить) | — |
| Дата окончания | Клик по дню календаря (после даты начала) | Нет | Максимум **21 день** (`MAX_DAYS`) — при превышении показывается предупреждение, но выбор не блокируется жёстко |

## Взаимодействия

### Выбор диапазона
- Первый клик — начало диапазона, второй клик (позже по календарю) — конец
- Живой пересчёт количества дней

### Продолжить
- **Действие:** `App.jsx` вычисляет `start_date`/`end_date` в формате ISO `YYYY-MM-DD` (`fmtDate`/`calcEndDate`) → `update({start_date, end_date})`
- **Переход:** к Шагу 4 (В каком стиле)

### Пропустить
- Отправляет `null` для обеих дат — поездка создаётся без дат

## Бизнес-правила / замечания
- **Критично:** если пользователь пропускает этот шаг (даты не заданы), при последующей попытке сгенерировать маршрут (Шаг 6) backend вернёт необработанное исключение (`ValueError` → HTTP 500) — «Для генерации маршрута у поездки должны быть указаны даты». UI Шага 6 покажет пользователю generic-ошибку без чёткого объяснения причины.
